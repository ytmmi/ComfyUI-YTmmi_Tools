# MOSS 实测规则（Field rules, measured）

本文件是 `moss-image-prompt-enhancer` 的参考资料，收录**在 MOSS-Image 上实测过**的落笔规则。
SKILL.md 只给决策入口，这里给细则。规则改编自上游 prompt-craft（MIT, Copyright (c) 2026 Luxvanyu）的
MOSS 实测规则全集（G1–G98），并保留本仓库的 Layout 默认口径。

## 第 0 步：先测再写

不要凭感觉写明度与饱和度。同一个 seed 下，把候选图按下面两件事量一遍再动笔：

- **明度三档**：把画面切成网格数一遍暗 / 中 / 亮各占多少（目标：暗 ≥30%、亮 ≤12%，
  一档主导 55–70%，三档**绝不均分**）；
- **饱和度方向**：分别看「受光处」与「阴影处」的色相强度，**两个方向必须实测**，
  不要假设「低饱和 = 高级」——饱和度高但受光处集中的画面才是阳刚，低饱和灰蓝是阴冷。

## A. 流程（4 条）

1. 每张图**先跑一遍上面的测量**再动笔；
2. 需要精确控色时，补一块色卡（16×11 的 hex 网格）当作参考；
3. 有现成的 NAI 元数据就照着读，**不要猜构图**；
4. **交付格式固定**：本仓库默认 Layout（见 SKILL.md「Choose the deliverable」）。

## B. 机位与透视（12 条，最容易翻车）

1. **不写形容词，写可验证的画面事实**：
   ✗ `from below` → ✓ `their ankles buried in the flowers`；
2. `full body` 会**吞掉机位词**，写全身时把机位写成几何事实；
3. `from below` + `foreshortening` + `wide angle distortion` 会画出脚底板，三者不要叠；
4. `directly overhead` 会退化成正常立姿，俯拍要写「前上方约 60 度」这种角度；
5. `dutch angle` 会被模型**摆正**，要写成「整幅画被顺时针旋转约 20 度」+ 点名三条不再水平的线；
6. 畸变要**具体到某个物体**（`the railing bends outward at the edges`），不要泛泛写 distorted；
7. 广角内倾**不能配中焦**；
8. 纵深靠**三层叠压**，不靠灭点；
9. 面积词是**几何指令**：`fills the top quarter` 真的会盖住天花板；
10. 空的暗区**不等于墙**：要写 `it is not a wall, not a building, not any solid thing, it is simply nothing`；
11. **可坐物比姿势词强势**：写了沙发，人就坐下了，不必再写 sitting；
12. 场景自带先验时要**显式否认**（比如「不是健身房」就别让它长成健身房）。

## C. 光（7 条）

1. 不要写成**布光说明书**：只给结果，不给器材与流程；
2. 「光的味道」= 五件物质性的事：碎光斑、透体发光、彩色反光、小幅过曝 + bloom 吃轮廓、空气介质；
3. 多个光源时写「**永不相混**」（`the two sources never mix`）；
4. **每个光源都要写衰减**（`the light dies within an arm's reach`）；
5. 近白像素 <1% 时，就写「**没有一处真正的白**」；
6. 反向光与投影要写具体（照到哪、投到哪、什么色）；
7. **不要自行加浓** god rays / high contrast——模型会替你加过头。

## D. 明度与色彩（7 条）

1. 一图一档主导，三档绝不均分；
2. 中调 85–90% = 插画感；中调 50–60% + 暗部三四成 = 电影感；
3. 饱和度方向必须实测（见第 0 步）；
4. **单色系最稳**；
5. 互补色必须有**第三色压场**；
6. 两个高饱和色**不要大面积直接相接**；
7. 留一个 **<5% 的小面积亮点**做视觉重音。

## E. MOSS 格式（6 条）

1. **只给正向**：不带 `masterpiece` / `best quality` / `ultra-detailed` / `high contrast`
   等质量词（MOSS 上无效且会挤占注意力；NAI v4.5 另有 81.5% 的提示词写 best quality，
   **这条禁令只对 MOSS 成立**，迁到别的模型时要去掉）；
2. 器材名 / 胶片名 / 渲染引擎名**无效**，不要写；
3. **光影与色温词放在人物 / 衣物名词之前**（MOSS 编码器从左往右读，前面的权重更大）；
4. JSON 分块要按「谁和谁一起动」分，不要按语义类别分；
5. `text` item 单独成块；
6. 角色名是 character caption 的**第一个词**：`名字, a girl ...`；
   作品名只出现在人物块，summary 与场景块里不许出现；
   原创角色写 `original character,`。

## G. 世界规则（挑最常踩的十条）

| 编号 | 规则 |
| --- | --- |
| G41 | 只写光的**落点**，不给光源名词 |
| G53 | 数值只能答「在哪 / 多大 / 多亮」，不能断言「画面里有没有某物」 |
| G63 | 要背面就写「背对我们」，不要写「没有脸」 |
| G64 | 提示词越长，人物被画得越大（实测 1.3–2.9 倍） |
| G65 | 人物默认不居中：主体放 1/3 处，另一侧**显式写成空** |
| G80 | 光斑要有「产出它的形状」的出处 |
| G84 | 水面自带俯视先验，要显式压掉 |
| G87 | 倒影必须被水面事件打断 |
| G90 | 要零文字时**先别叫它招牌** |
| G93 | 两人同框时，两人的上边必须相差 ≥ 画高的 8% |

## 交付形态：Caption vs Layout

- **Caption**：普通场景的散文描述，上游 MOSS 的默认；
- **Layout**：`summary.caption`（全局）+ `items`（每个局部单元一个 bbox），
  用于落字、海报、多格、物体关系受控的画面。

**本仓库的口径：默认 Layout。** 上游把选择权交给用户，普通场景回退 caption；
本仓库因为下游工作流要消费版面信息，所以**故意**让 Layout 成为默认，caption 是兜底。
两者不冲突，只是默认值相反——写交付说明时不要把上游的默认说成自己的默认。

## 编译常见坑

- 框超出画布 → 编译报错，**不要手动居中绕过**，改草稿；
- 尺寸不是 16 的倍数 → 编译报错；
- 未知字段（如 `summary` 里的多余键）→ 编译报错；
- 文本里的换行要按 JSON 转义写出，编译结果才是单行。
