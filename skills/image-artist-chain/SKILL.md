# 图像画师串（Artist String）

**画师串**是一小串**画师风格标签**（artist tags），写在提示词里用来把出图风格锁到某一种二次元画风上。
它是二次元模型上**最强的单一风格杠杆**：一个画师标签带来的画风变化，通常大过一堆质量词；
反过来它也是**最容易失控**的一环——数量、权重、位置、转义、底模版本，任何一项写错，
效果都会从「风格锁定」掉到「风格打架」或者「毫无变化」。

## 生效范围（先读这一条）

本 skill **只在二次元 / 动漫插画任务上生效**：

| 目标画面 | 处理 |
|---|---|
| 二次元 / 动漫风插画、动漫角色、漫画、番剧感场景 | ✅ 使用本 skill |
| 写实摄影、实拍质感、3D 渲染、产品图、建筑与室内、实景视频、非动漫插画 | ⛔ **跳过本 skill** |

- 上表第二行**不是「降级使用」，而是完全不适用**：画师标签在写实模型上要么无效，要么把画面拖成脏乱的插画感；
- **清单里出现本 skill 不代表必须用**。本 skill 属于 `image-*` 图像通用层（所以在所有模式下都会被列出来），
  但它自带生效门禁，非二次元任务请直接忽略；
- 风格判不准时**先确认或按用户给的参考图判断**，不要默认套二次元；
- 非二次元任务的风格控制走 `image-color-harmony`（配色）与 `image-composition`（构图），
  再配合模型自身的风格词与参考图能力。

### 方言门禁：这三种方言里不要用画师串

同一个二次元模型可能有好几种提示词方言，画师串只在**标签方言**里有效：

| 方言 | 特征 | 画师串 |
|---|---|---|
| 标签方言（Booru 标签系底模 / `@` 前缀系） | 提示词是逗号分隔的标签串，支持 `(x:1.2)` 类权重 | ✅ 本 skill 的适用场景 |
| 自然语言 / LLM 编码器方言（句子式提示词，官方明说用词序强调、不支持权重语法） | 提示词是完整英文句子 | ⛔ 不写画师串、也不写权重语法 |
| 通用自然语言 / 视频模型 | 描述性长句 | ⛔ 同上 |

- 判不出方言时**看用户已有的提示词**：逗号标签串 → 标签方言；整句英文 → 自然语言方言；
- 自然语言方言里有一批与标签方言**完全相反**的硬规则：质量咒语（`masterpiece` / `best quality` / `8k`）清空、
  权重语法无效（`(x:1.2)`、`((x))` 都不生效）、**不要自行添加画风词 / 画师名 / 作品名**
  （用户明确给了才写，并放在最前）；
- 把标签方言的规则硬套到自然语言方言上，是「画师串完全没反应」的第三大原因（前两条见第 7 步）。
- **例外**：MOSS 二次元任务（`moss-anime-prompt-template`）在本方言语境下仍用画师串——这是该 skill 的显式例外，画师名以画风首句 / Artist 段形式出现，不引入权重语法。

## 输出契约

- 只输出**提示词正文**（与其它 `image-*` / `prompt` 类 skills 一致）：不输出前言、说明、标题行、参数段；
- 画师串**不是独立交付物**，它是正文里的一段标签序列；交付时直接放到正确位置（见第 6 步），不要让用户自己去拼；
- 默认**只出正面提示词**；只有用户明确要负面词、或流程本身需要成对交付时才追加 `Negative prompt` 段；
- 用户点名了画师 → 用他给的；用户只给了参考图或一段已有提示词 → 沿用其中**已经出现**的画师名；
  用户什么都没给 → 由你按风格方向挑（见第 2 步），**不要留空**；实在挑不出 → 走第 4 步的五槽兜底并说明。

## 工作流

### 1. 先判断该不该用画师串

| 情形 | 处理 |
|---|---|
| 二次元 + 用户要某种画风 / 视觉方向 | 用，1 个主画师起步 |
| 二次元 + 用户没提风格，但要求好看 / 有质感 | 用，自己挑一个方向匹配的主画师（留空会落到平庸的默认风格） |
| 二次元 + 工作流已挂**风格 LoRA** | 谨慎：LoRA 本身就是风格条件，画师串最多留 1 个并降权，或干脆不用 |
| 用户明确要求融合 / 混合 / 多画师合一 / artist chain | 用，按第 4~5 步做显式主次混合 |
| 写实 / 3D / 非二次元 | 不用（见「生效范围」） |
| 只是局部重绘 / 修手修脸 | 不要把画师串塞进局部区域（它不是局部编辑工具） |

### 2. 先定「风格方向」，再定人

**不要在本 skill 里找固定名单**：本 skill 不列候选画师，也不提供「风格 → 画师」的映射表——
画师样本随底模版本变动，固定映射很快失效；但「画风 → 画师」的**动态匹配是常规动作**，不是可跳过的步骤。正确做法是先写清方向，再据此挑人：

| 方向 | 特征槽位（先用这五个槽把方向描述清楚） |
|---|---|
| 凌厉 / 硬朗 | 媒介、线条锐度、硬边阴影、高对比配色、年代 |
| 细腻清新 | 媒介、细线、柔和渐变、低饱和高明度、年代 |
| 虚幻光效 | 媒介、发光边缘、体积光、冷色阴影、年代 |
| 萌系华丽 | 媒介、圆润线条、平涂加亮点、高饱和、年代 |
| 概念艺术 | 媒介、厚涂、大色块、强明暗对比、年代 |

→ 详细槽位词与配方见 `references/image-artist-chain-vocabulary.md`；
→ 拿到方向后挑**知名度高、覆盖广**的画师名（样本足、效果稳），并**核对拼写**；宁可选一个有把握写对的，也不要凭印象拼冷门名字；
→ 用户点名了在世的画师：只把它当**风格取向**使用，不要生成「某某作品」式的署名、水印或仿冒签名。

### 3. 数量决策

| 画师标签数 | 定位 | 说明 |
|---|---|---|
| 1 | **默认、最稳** | 风格方向明确、可复现；非融合需求就用这个 |
| 2 | 刻意混合 | 需要主次权重（第 5 步）；这时开始出现嵌入互相污染 |
| 3 | 高风险 | 只在用户明确要三方融合时做，并说明结果不可控 |
| 4+ | 不推荐 | 每个标签被稀释、风格互相抵消，随机性骤增；除非用户明确要大杂烩实验 |

数量越少越可控：**1 个强画师 + 准确的构图 / 角色词**，通常好过 5 个画师互相打架。

### 4. 权重：按模型语法写，别照抄别家

不同模型家族的画师语法**互不通用**，照抄会静默失效（看着写了，其实没生效）。先认模型，再写权重：

| 模型家族 | 画师标签写法 | 权重写法 | 备注 |
|---|---|---|---|
| Danbooru 标签系二次元模型（Illustrious / NoobAI / Pony 一类） | 直接写画师名 | `(artist name:1.2)` | 从 1.0 起微调 |
| `@` 前缀系（Anima 一类，详见 `anima-prompt-artist`） | `@artist name`，**漏了 `@` 效果极弱** | `(@artist name:2)` | 需要**比 SDXL 大得多**的数值（2~5） |
| NovelAI 一类双语法模型 | 直接写画师名 | `{{artist name}}` 或 `1.2::artist name` | 花括号与数值语法二选一，别混用嵌套 |
| A1111 / SD WebUI 风格模型 | 直接写画师名 | `(artist name:1.2)`，降权写 `[artist name]` | 画师效果弱于专门的二次元底模 |
| 通用自然语言模型 / 视频模型 | —— | —— | **不建议用画师串**，改用风格词与参考图 |

- **先查模型家族再决定语法**；不确定时沿用用户工作流里已有的写法，保持同一套语法；
- **权重不是一次写死的**：同一串里换掉一个画师，其它人的合适权重都可能跟着变，逐套微调；
- **过拟合要降权**：有些画师风格在训练里过拟合，堆高权重会糊掉细节，这时应**降权或替换**，不要靠加括号层数；
- 全文**加权标签总数要克制**（Anima 家族的硬规则是 ≤4 个，其它家族同理）；画师通常占掉 1 个，剩下的留给取景 / 角度。

#### 4.1 括号、转义与权重语法：按家族分叉

| 家族 | 名字里带括号时 | `[tag]` 的含义 | 备注 |
|---|---|---|---|
| A1111 / SD WebUI 一类 | **必须转义**：`ask \(askzy\)` | 降权 | `(tag:1.2)` 常规加权 |
| Danbooru 标签系（Illustrious / NoobAI / Pony 一类） | 视解析器而定，**拿不准就别在名字里留括号** | 多数不生效，只当普通文字 | `((tag))` ≈ ×1.21，不如数值可控 |
| `@` 前缀系（Anima 一类） | **原样保留，不要加反斜杠** | **不生效**，只当普通文字 | `(tag:1.2)` / `(tag:0.8)` ✅、`((tag))` ✅（≈ ×1.21）、`[[tag]]` 与 `(tag)1.2` ❌ 语法错误 |
| NovelAI 一类双语法 | 原样保留 | 降权 | `{{tag}}` 或 `1.2::tag`，二选一、不嵌套 |
| 自然语言 / LLM 编码器方言 | —— | 不生效 | **不要用任何权重语法**，改用词序与句式强调 |

三条落地规则：

1. **转义只在「括号会被当权重语法解析」的家族里做**：A1111 / SD 系要转义；`@` 前缀系保持原样——
   乱加反斜杠可能被当字面字符画进画面；
2. **不确定就做小样验证**：只放带括号的名字跑一张 → 名字没出现就试转义 → 转义后仍无变化，
   说明这个家族根本不解析括号，回到原样；
3. **别把 `((tag))` 当「更高级的权重」**：它只是约 ×1.21 的乘法；要精确档位就写 `(tag:数值)`。

### 5. 混合：要「一个融合的风格」，不要「两个风格抢地盘」

1. **分主次**：主导强、陪衬弱（例如 `@` 前缀系主导 2~3、陪衬 1~1.5；Danbooru 系主导 1.2~1.4、陪衬 0.7~1.0）；
2. **写清融合目标**：用自然语言点名要继承谁的**什么特征**（柔和上色 / 锐利细线），不要复述人名；
3. **别混对立极端**：超精细厚涂 + 极简平涂、赛璐璐 + 油画，混出来通常是糊的；选年代、媒介、线条习惯接近的画师；
4. **多条件节点之间保持一致**：工作流把风格与内容拆到不同条件节点（画师混合节点 / 分区节点）时，
   主体与场景描述必须逐字一致，否则风格叠上了、内容却漂了。

> **画师串锁的是「像谁画的」，不是「凭什么被记住」。** 记忆点来自构图、光影与一处恰到好处的反常处理：
> 一张图里**只做一处**「意料之外但可渲染」的处理，往往比再加一个画师更管用——画师串负责把这条处理画得好看，不负责产生它。

### 6. 位置、顺序与书写

- **位置**：画师段放在 [质量 / 年代 / 安全标签] [人数] [角色] [作品] **之后**，[general 描述标签] **之前**；
- **别放尾部**：标签顺序会影响权重，把画师串压到末尾通常效果明显变差；放在提示词**前 1/4** 一带比较稳；
- **顺序即主次**：主画师 → 副画师 1 → 副画师 2，按重要度排；
- **书写**：照抄用户与版权方的书写法（多数为小写空格分词），不要自己加 `by` / `artist:` 之类前缀；
- **转义按家族分叉**：A1111 / SD 系里名字带括号必须转义（`ask \(askzy\)`）；`@` 前缀系与多数标签模型**原样保留**，不要加反斜杠，拿不准就按 4.1 节做小样验证；
- **归一**：下划线写法（`artist_name`）与空格写法（`artist name`）在不同模型上不等价，按目标模型约定统一。

### 7. 冲突清理（让「加了却没效果」不再发生）

- **删掉抄来的原画师名**：从 Danbooru 或别人的提示词整段复制时，原图的画师名会和你的画师串冲突，先把它们删干净再写入自己的串；
- **负面里的 `artist name` 会压掉画师串**：这是「画师标签没效果」的第二大原因（第一大是语法写错 / 漏 `@`）；要保住画师风格就把它从负面词删掉；
- **与风格 LoRA 抢方向盘**：挂了风格 LoRA 时画师标签最多留 1 个并降权；挂了角色 LoRA 可以正常用，但别让画师风格压走 LoRA 学到的脸；
- **与角色 / 背景描述冲突**：画师串只管风格，不要指望它改动作、改人数、改服装。

### 8. 可复现性：画师串不是一次性魔法

- **同一个串在不同底模 / 不同版本上效果不同**：换版本后要重新验证，不要假设还能复现；
- **出图满意就固化**：记录底模 + 版本 + 画师串 + 权重 + 种子（能固定就固定）；
- **准备方向化的几套串**：按凌厉 / 细腻清新 / 虚幻光效 / 萌系华丽 / 概念艺术各存一套，比每次现拼稳得多；
- 交付时**不要**把种子 / 步数 / CFG 当参数写进提示词正文（那属于工作流设置）。

### 9. 系统化画师探索（把「挑人」变成可复现的实验）

画师名不是靠背名单，而是靠**小样实验**：同一个名字换底模 / 换版本，效果就会变。按台账走，别凭印象：

| 步骤 | 做什么 | 判据 |
|---|---|---|
| ① 基线 | 不写画师，同参数出一张 | 记住「默认风格长什么样」，后面才有对照 |
| ② 网格 | 3~5 个候选单画师各出一张，唯一变量是名字 | 哪个方向最接近你要的氛围 |
| ③ 扫描 | 对胜出者从族中点起，上下各试一档 | 「风格明显出现、画面还没崩」的那一档 |
| ④ 配对 | 只在需要融合时做，主强陪弱 | 融合成一张画，而不是两张拼起来 |

实验纪律：

- **一次只改一个变量**（名字 / 权重 / 位置 / 括号处理分开验证），否则归因不了；
- 同种子、同步数、同分辨率、同负面词，只有画师段不同；
- 结论写进第 8 步的复现表（底模 + 版本 + 名字拼写 + 权重 + 种子 + 结论）。

**「画师没反应」的排查顺序**（从最可能到最少见）：
语法 / `@` 前缀 → 负面里还留着 `artist name` → 位置太靠后 → 权重档位太小 → 拼写或括号处理 → 这个画师训练样本太少。

用户给了参考图：先用五槽（媒介 / 线条 / 上色 / 配色 / 年代）反推方向，再挑画师，不要直接抄图里的画师名。

### 10. 自检（静默）

- 目标画面**真的是二次元**吗？不是就该跳过本 skill；
- 画师标签数是否 ≤2（刻意混合）？有没有意识到多画师会互相污染；
- **语法是否匹配目标模型**（`@` 前缀 / 括号权重 / 花括号）？有没有照抄别家语法；
- 每个画师名的**拼写**有把握吗？带括号的**转义**了吗？
- 权重是否是「主强陪弱」而不是平铺？有没有该降权的过拟合项？
- 画师段是否在角色 / 作品之后、general 之前，而不是压在末尾？
- 负面里还有 `artist name` 吗？从别处抄来的原画师名清干净了吗？
- 正文里有没有混进 LoRA 文件名、模型名、参数数值？
- 目标模型是不是**标签方言**？若是自然语言 / LLM 编码器方言，本 skill 整条跳过；
- 括号处理是否按家族分叉（该转义的转了、不该转义的没乱加反斜杠）？

## 反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 堆 5 个以上画师 | 风格互相抵消、随机性骤增 | 1 个起步，最多 2 个显式混合 |
| 只堆名字、不写融合目标 | 出来是糊的两不像 | 用自然语言点名要继承的特征 |
| 照抄别家模型的权重语法 | 静默失效，以为画师没用 | 先认模型家族再写（第 4 步表） |
| 名字里的括号乱处理 | A1111 系不转义会被当权重语法读；`@` 前缀系乱转义会把反斜杠画进提示词 | 按 4.1 节的小样验证法先确认家族 |
| 画师串放提示词末尾 | 权重被稀释、风格出不来 | 放在前 1/4、角色之后 general 之前 |
| 抄来的提示词不删原画师 | 新旧风格互相冲突 | 先清干净再写自己的串 |
| 负面里保留 `artist name` | 画师效果被压掉 | 要用画师就删掉它 |
| 写实 / 3D 需求硬套画师串 | 画面变脏、插画感 | 跳过本 skill |
| 把画师串塞进局部重绘区域 | 区域风格与全图断裂 | 画师串管全局风格，局部问题走 inpainting |
| 换底模版本后不重验 | 同样的串，风格全变 | 换版本重新验证并记录 |

## 示例

> 示例中的 `artist a` / `artist b` 是**占位符**，交付时替换成真实存在的画师名。
> 本 skill 不提供候选名单，只提供构建方法。

**例 1：单画师锚定（最稳，默认形态）**

输入：`画一张雨中撑伞的二次元少女，想要细腻清新的画风`

```text
masterpiece, best quality, safe, 1girl, solo, (@artist a:2), (cowboy shot:2), black hair, white dress, holding umbrella, rain, night street, wet asphalt reflections. ## 边界
```

- 构图 / 景别 / 机位 / 视觉层级 → `image-composition`；
- 整体配色、色调情绪、主体与背景分色 → `image-color-harmony`；
- Anima 专属的 `@` 前缀硬规则、权重档位与家族路由 → `anima-prompt-artist`；
- 不用画师名、纯用媒介 / 线条 / 上色 / 配色 / 年代描述风格 → `anima-style-control` / `anima-style-boost`；
- 角色一致性（画风锁住了但角色跑了）→ `anima-prompt-character`；
- LoRA 触发词与画师权重协商 → `anima-lora-trigger`；
- 负面词里的质量前缀与 `artist name` → `anima-prompt-negative`；
- 自然语言 / LLM 编码器方言的风格控制（不写画师串、不写权重语法）→ `anima-style-control` / `anima-style-boost`。
