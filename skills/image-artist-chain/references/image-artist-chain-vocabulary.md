# 画师串词表与配方（Artist String Vocabulary）

本文件是 `image-artist-chain/SKILL.md` 的参考词表与配方库：语法对照、权重档位、方向词表、混合模板、追查清单。
本文件**不列候选画师名单**——名单会随底模版本失效，方法不会。

## 1. 使用规则

1. **先认模型，再写语法**：不同模型家族的画师语法互不通用，照抄会静默失效；
2. **一次只改一个变量**：数量 / 权重 / 位置 / 转义分开验证，别一次全改导致归因不了；
3. **权重逐套微调**：同一串里换人，其它人的合适权重会跟着变，没有通用参数；
4. **过拟合靠降权、不靠加层**：风格糊了先降权或换人，不要靠括号层数硬顶；
5. **只服务二次元**：写实 / 3D / 实景需求不进本流程。

## 2. 模型语法对照

| 家族 | 无权重 | 加权 | 降权 | 备注 |
|---|---|---|---|---|
| Danbooru 标签系（Illustrious / NoobAI / Pony 一类） | `artist name` | `(artist name:1.2)` | `(artist name:0.8)` | 小数权重，1.0 起步 |
| `@` 前缀系（Anima 一类） | `@artist name` | `(@artist name:2)` | `(@artist name:0.8)` | 数值档位明显更大（2~5） |
| NovelAI 一类双语法 | `artist name` | `{{artist name}}` 或 `1.2::artist name` | `[artist name]` 或 `0.8::artist name` | 花括号与数值语法二选一，不要嵌套混用 |
| A1111 / SD WebUI 风格 | `artist name` | `(artist name:1.2)` | `[artist name]` | 画师效果弱于专用二次元底模 |
| 通用自然语言 / 视频模型 | —— | —— | —— | 不建议用画师串 |

判定流程：

1. 用户工作流里已有的提示词用的是哪种写法？照做；
2. 没有线索时，看模型名 / 底模社区：标签系二次元底模走第 1~2 行，视频与通用模型直接放弃画师串；
3. 写完后**先小样验证**：画师特征完全没出现，优先怀疑语法与 `@` 前缀，而不是权重太小。

### 2.1 括号、转义与权重语法（家族分叉）

同一个名字，在不同家族里该不该转义是**相反**的——这是「照抄别家写法」最容易踩的坑：

| 家族 | 名字带括号 | `[tag]` | 权重语法 |
|---|---|---|---|
| A1111 / SD WebUI 一类 | **必须转义**：`ask \(askzy\)` | 降权 | `(tag:1.2)` ✅ |
| Danbooru 标签系 | 拿不准就别留括号 | 多数不生效 | `(tag:1.2)` ✅；`((tag))` ≈ ×1.21，不如数值可控 |
| `@` 前缀系（Anima 一类） | **原样保留，不要加反斜杠** | **不生效**（只当普通文字） | `(tag:1.2)` / `(tag:0.8)` ✅、`((tag))` ✅（≈ ×1.21）、`[[tag]]` ❌、`(tag)1.2` ❌ |
| NovelAI 一类双语法 | 原样保留 | 降权 | `{{tag}}` 或 `1.2::tag`，二选一、不嵌套 |
| 自然语言 / LLM 编码器方言 | —— | 不生效 | **不要用任何权重语法**，用词序与句式强调 |

判定与验证：

1. **先认家族**（第 2 节对照表）→ 再决定括号怎么处理；`@` 前缀系乱加反斜杠，反斜杠可能被当字面字符画出来；
2. **小样验证**：只放这一个带括号的名字跑一张 → 名字没出现就试转义 → 转义后仍无变化 → 说明该家族不解析括号，回到原样；
3. **别拿 `((tag))` 当更高档位**：它只是约 ×1.21 的乘法；要精确档位就写 `(tag:数值)`。

## 3. 权重档位与微调

| 档位（相对该模型的中点） | 效果 | 何时用 |
|---|---|---|
| 明显低于中点 | 只当点缀，风格隐约可见 | 陪衬位、LoRA 共存时的保守档 |
| 中点 | 常规起点，风格明显主导 | 单画师锚定（默认） |
| 高于中点 | 强强调，其它细节开始被压 | 主画师定调、风格必须压过别家 |
| 极高 | 构图与细节被一起改写 | 只做风格实验，不进正式交付 |

微调流程：

1. 先写**单画师**，找到「风格明显出现、画面还没崩」的那一档，记下来；
2. 需要混合时，主画师沿用上一档，陪衬从**主画师的 1/2** 起试；
3. 陪衬的特征只在部分区域出现就够；如果陪衬把主线画风搅乱，降陪衬而不是升主画师；
4. 画风糊 / 线条脏 / 细节消失 → 降权或换人，不要加层数；
5. 全程遵守「加权标签总数克制」的家族硬规则（`@` 前缀系 ≤4）。

## 4. 风格方向 → 五槽词表

用户没说画师名、或需要描述「不要画师的效果」时，按五个槽各取 1~2 个词：

| 方向 | 媒介 | 线条 | 上色 | 配色 | 年代 |
|---|---|---|---|---|---|
| 凌厉 / 硬朗 | `digital painting`, `ink drawing` | `sharp lineart`, `thick outlines` | `hard shading`, `high contrast shading` | `high contrast`, `muted colors` | `retro artstyle`, `year 2000s` |
| 细腻清新 | `watercolor`, `digital painting` | `thin lineart`, `clean lineart` | `soft shading`, `gradient shading` | `pastel colors`, `muted colors` | `newest`, `year 2020s` |
| 虚幻光效 | `digital painting`, `concept art` | `clean lineart` | `soft shading`, `dappled light` | `vibrant colors`, `cold palette` | `recent`, `year 2010s` |
| 萌系华丽 | `cel shading`, `flat color` | `rounded lineart`, `thick outlines` | `flat color`, `hard shading` | `vibrant colors`, `saturated colors` | `newest`, `year 2010s` |
| 概念艺术 | `oil painting`, `concept art` | `sketchy lineart`, `no lineart` | `dappled light`, `gradient shading` | `limited palette`, `sepia` | `early`, `mid` |

词表只用于「方向描述」；要锁定**具体画风**仍然优先用画师串（在允许使用的二次元模型上）。

## 5. 混合配方

**配方 A：主 + 陪衬（2 人，默认混合形态）**

```text
[质量/安全标签], [人数], [角色], [作品], (主导画师:主导档), (陪衬画师:主导档的一半), [general 标签]. 
自然语言：保留主导风格的 <特征>，借入陪衬风格的 <特征>，融合成一张一致的画。
```

**配方 B：三方融合（3 人，高风险）**

```text
(主导画师:主导档), (副一:主场档 × 0.6), (副二:主场档 × 0.4)
```

- 三方只在用户明确要求时做，并**在交付时说明结果不可控**；
- 三个人里至少有两人的媒介 / 年代接近，否则优先劝用户降到两人。

**融合目标句模板**（用特征，不复述人名）：

```text
keep the <shading / palette / lineart> of the dominant style while borrowing <feature> from the accent style,
the two influences blended into one consistent drawing rather than two styles competing.
```

## 6. 位置与顺序模板

```text
[质量][年代][安全]  [人数]  [角色]  [作品]  [画师串]  [general 描述]  自然语言补充
```

- 画师串**在角色 / 作品之后、general 之前**；
- 整条提示词的前 1/4 一带最稳；压到末尾通常明显变差；
- 串内顺序 = 主次顺序（主导 → 陪衬一 → 陪衬二）。

## 7. 转义与书写检查表

- [ ] 括号处理按家族分叉（第 2.1 节）：A1111 / SD 系转义，`@` 前缀系与多数标签模型**原样保留**；
- [ ] 下划线写法与空格写法按目标模型统一，不要同一串里混用；
- [ ] 拼写逐字核对——宁可选一个能确认的，也不要用一个没把握的冷门名字；
- [ ] 不要自己加 `by` / `artist:` / `style of` 前缀；
- [ ] 不要生成对在世画师的署名、水印、仿冒签名，画师名只作为**风格取向**。

## 8. 多条件节点的一致性

工作流把风格与内容拆开时（画师混合节点 / 分区提示词 / 多条件叠加）：

1. **主体与场景描述逐字一致**：各条件节点里的角色、动作、场景文本必须相同，只有画师段不同；
2. **风格串按主次排序**：主风格 → 副一 → 副二，顺序本身带权重意义；
3. **不要在局部区域用画师串做局部编辑**：区域级差异应该用分区提示词或 inpainting，不是换画师；
4. **改一处就复验**：节点叠加出的效果无法从单条提示词推断，改了就重跑对比。

## 9. 可复现性记录表

满意的成图立刻固化下面这几列，换版本时先按表复验：

| 底模 | 版本 | 画师串 | 权重 | 种子 | 采样器 | 结论 |
|---|---|---|---|---|---|---|
| 例：二次元底模 A | v1.0 | artist a + artist b | 3 / 1.5 | 12345 | 默认 | 稳定，可量产 |

提醒：**底模换版本后同一串的效果会变**，上一次的结论不能直接沿用。

## 10. 发运前清单

- [ ] 目标画面确实是二次元 / 动漫插画（否则退出本流程）；
- [ ] 画师数量 ≤2（或用户明确要求三方融合）；
- [ ] 语法与目标模型匹配，`@` 前缀该带的都带了；
- [ ] 权重是主强陪弱，且加权标签总数没超标；
- [ ] 位置在角色 / 作品之后、general 之前，不在末尾；
- [ ] 名字拼写已核对，括号已转义；
- [ ] 负面词里没有 `artist name`，抄来的原画师名已清干净；
- [ ] 与风格 LoRA 的冲突已处理（最多 1 个画师并降权）；
- [ ] 正文里没有混进参数、模型名、LoRA 文件名；
- [ ] 交付时没承诺「一定复现」（换版本会变）。

## 11. 常见失败 → 修法

| 现象 | 最可能的原因 | 修法 |
|---|---|---|
| 加了画师串，风格几乎没变 | 语法不对 / 漏 `@` 前缀 | 按第 2 节对照表重写语法 |
| 风格出来了但画面变脏、细节糊 | 权重过高或画师过拟合 | 降权，或换一个风格相近但不过拟合的人 |
| 两个风格打架、像两张画拼起来 | 没有主次、或混了对立极端 | 拉开权重差，换掉年代 / 媒介差距大的那个 |
| 画师效果忽有忽无 | 位置太靠后、或负面里还留着 `artist name` | 挪到前 1/4，删负面的 `artist name` |
| 名字明明写了却没生效 | 该转义的没转义（A1111 系），或被别家语法吃掉 | 按第 2.1 节先认家族，再小样验证转义 |
| 换底模版本后风格全变 | 画师样本随版本变动 | 重新标定权重，更新记录表 |
| 风格锁住了但角色 / 动作跑了 | 用风格条件承担了内容职责 | 补齐角色与构图描述，交给 `image-composition` |
| 在句子式提示词里写画师串 | 该方言不解析权重与画师标签，画师串整体失效 | 改走风格词 / 参考图（见 SKILL.md 的方言门禁） |

## 12. 画师探索台账

画师名靠实验而不是靠名单。照下表跑，结论写进第 9 节：

| 步骤 | 操作 | 唯一变量 | 记录 |
|---|---|---|---|
| ① 基线 | 不写画师，同参数一张 | 无 | 默认风格基线 |
| ② 网格 | 3~5 个候选各一张 | 画师名 | 哪个方向最接近目标 |
| ③ 扫描 | 胜出者从中点上下各一档 | 权重 | 「风格出现、画面没崩」的档位 |
| ④ 配对 | 需要融合时才做 | 陪衬及其权重 | 是融合还是打架 |

- 同种子、同步数、同分辨率、同负面词；
- 一次只改一个变量，改两处就归因不了；
- 结论必须带**底模 + 版本**：换版本后要重跑第 ③ 步。

## 13. 不生效排查（按顺序）

1. 语法 / 漏 `@` 前缀（第 2.1 节）；
2. 负面里还留着 `artist name`；
3. 画师段压在提示词末尾（挪到前 1/4）；
4. 权重档位对该家族太小；
5. 名字拼写或括号处理；
6. 该画师样本太少——换一个更知名、覆盖更广的。
