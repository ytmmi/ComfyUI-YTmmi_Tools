# MOSS 二次元提示词模板（sfw 版）

把用户的画面需求直接写成 **MOSS-Image-Base / MOSS-Image-SFT 可用的正向提示词**。
覆盖普通二次元人物、IP 同人、场景插画、多人互动、海报与漫画。

本文件是**完整可执行的硬规则**（不是索引）：渐进式披露只返回本 SKILL.md，不会自动
返回 `references/` 下的文件，所以所有判定条件、禁止项与坐标换算都写在这里。
`references/` 保留原始中文模板全文与英文执行指令，仅在需要逐条比对或整段转交时读取：

- `references/anime-prompt-template-zh.md` —— 原《MOSS 二次元提示词模板（sfw 版）》完整正文（§1–§16）；
- `references/execution-instruction-en.md` —— §17 英文执行指令，可整段交给英文环境的写词模型。

> 本 skills 只做提示词改写：**不生成图片、不调用外部 API、不执行任何脚本**，
> 也不把分辨率、种子、步数、CFG、采样器、模型路径写进输出。

## 输出契约（必须遵守）

**只输出最终正向提示词正文本身**，不复述规则、不展示内部规划表、不加开头说明或结尾建议、
不加 Markdown 代码块围栏（除非用户明确要 JSON 便于复制）。

三种交付形态，先按 §2 决策树选：

| 用户要的结果 | 正向框真正接收什么 | 其他信息放哪 |
|---|---|---|
| 普通插画 Caption | 连贯纯文本（英文默认，中文按需） | 必要说明在正文之外 |
| Tag 串 | 逗号分隔的有效内容词 | 不加权重、不加分角色/区域扩展语法 |
| Layout | 单行紧凑 JSON（`abs_centralized` / `yxyx`） | **必须在提示词外注明出图尺寸**，并保留草稿 |

### 语言

- **默认只输出英文正向提示词**；用户明确要求中文时只输出中文；要求双语时给**两份各自完整、
  语义一致的独立版本**（不是把两种语言塞进一次生成）。
- Layout 的字段名与枚举始终用官方英文（`summary` / `items` / `character` / `object` / `text`），
  `caption` 等自然语言描述值按所选语言写；不能把 `summary` 翻译成「摘要」。
- 图片里真正要出现的字，**保留用户给定原文、大小写、标点与换行**。英文提示词也可以生成
  中文标题「星海咖啡」。
- 判断语句是「描述」还是「可见文案」：「气氛像『雨后初晴』」通常是创作说明，不代表要把
  「雨后初晴」印在图上。
- 角色名、作品名保留有辨识度的原名或别名；这不等于把整段描述写成中英重复段落。

### 禁止项（硬规则）

不自动加入**质量 tag、评分 tag、画师姓名、`@artist`、负向提示词、采样器、步数、CFG、
模型路径和解释文字**。不得通过 `meta`、`tags`、`palette` 等 JSON 字段绕过这条规则。

即不生成 `masterpiece`、`best quality`、`highres`、`score_9` 一类质量前缀；也不擅自抽画师。
用户明确指定画风名称时按 §1.4 处理，**不自动附加其他画师**。

**可以写具体视觉方式**：`Japanese 2D anime illustration`、`layered cel shading`、
`colored linework`、`painterly background`、`limited teal-and-amber palette`。
它们描述媒介、线条、上色与配色，与空泛质量前缀不同。

**SFW 边界**：保持普通角色创作语境，不擅自改变年龄、性别、体型，不加入性化姿势；
明确未成年 IP 的普通插画保持正常活动与着装，不借「美学」自动转成人分支。

### 画风必须是独立首句

画风按优先级确定：**用户指定的画风或参考图 → 用户要求的表现方式 → 根据题材补充默认方案**。
参考图中的画风转写为文字；未指定时合理补充简短描述，**不建立或强制套用画风库，
不自动抽取画师或工作室**。

画风描述单独组成**一句话，置于提示词最前面**，只写整体视觉表现。用户明确指定的画师、导演
或工作室风格名称可保留在这一句；需要时在同一句内补少量线条、上色或背景处理特征，
**不扩写成多句分析**。

- **Caption**：第一句为画风句，随后接完整的角色、衣装、动作、构图、场景与光影正文。
- **Layout**：画风句为 `summary.caption` 的第一句，后接原有全局描述；**不新增 `style` 字段**，
  不在各个 item 中重复画风句。
- **Tag**：画风句放在标签串之前，其后内容标签保持原有相对顺序。
- **仅改画风时**：只替换首句；后面的角色、衣装、动作、构图、场景、光源描述及 Layout 框
  保持不变，不为迎合画风擅自换装、换地点或改剧情。

正文中原有的环境光照、材质与空间描述继续保留；画风首句**不代替**它们。

## §2 格式选择决策树

先服从用户明确指定的 Caption / Tag / Layout，再处理未指定的情况。

```text
是否明确要坐标框 / Layout / 指定区域排版？
  是 → Layout；先确定画布，再写草稿并编译。
  否 → 是否需要多处独立文字或图块的位置、比例和阅读顺序？
          是 → 优先 Layout。
          否 → 是否只是「左边一个人、右边一扇窗」等大致空间关系？
                  是 → 先用 Caption；需要固定占比时再升级 Layout。
                  否 → 普通人物、美学场景、姿势与角色创作默认 Caption。
```

| 需求 | 默认选择 | 判断理由 |
|---|---|---|
| 角色在玻璃温室里听歌，脸部有窗光 | Caption | 重点是角色、光影和气氛，位置无需数字框 |
| 广角海底遗迹、复杂透视、飞行战斗 | Caption | 场景复杂不等于需要坐标；透视和受力仍靠描述 |
| 两人交谈，大致左右站位 | Caption | 两段独立人物描述通常足够，先不增加坐标负担 |
| 左右两人必须占指定区域，中间留箱子 | Layout | 人物与道具的占位、比例是主要约束 |
| 单句文字写在人物手中卡片上，位置不严格 | Caption | 写清载体和实际文字即可 |
| 上方标题、右侧三行文案、左侧人物 | Layout | 多个独立信息块需要层级与位置 |
| 二格/四格漫画，各格动作不同 | Layout | 每格及文字需全局规划；不保证跨格脸一致 |
| 只改图中文字或只移动一个对象 | Layout 可规划新生成 | 改 JSON 后是重新生成，不是局部图像编辑 |
| 用户只想把提示词存成 JSON 文件 | Caption 草稿也可用 JSON 存储 | 这是文件包装，不等于启用 Layout |
| 左右手错、手指错、表情不对 | 先修 Caption 的语义与动作 | bbox 不描述手部关节，不是姿态骨架 |
| 想要更好看但没有位置约束 | 先完善美术设计 | JSON 不是美学增强开关 |

**不应自动切 Layout**：仅仅因为提示词长、角色知名、画面细节多、想要电影感、单人动作复杂、
需要手指准确，都不构成切 Layout 的理由。用户要极简立绘时也不强行增加标题、页脚、装饰模块。
大致左右关系直接写自然语言即可。

**草稿与最终提示词是两种东西**：普通 Caption 输出纯文本即可；若用 `{"caption":"..."}` 保存
描述，真正的提示词是其中的文本值。Layout 的左上角像素草稿与中心坐标成稿不可混用（见 §12）。

## §3 需求解析与默认补全

写词前在内部建立下表，**不要求用户填表，也不把规划表混进最终输出**。

| 项目 | 必须保留/明确的内容 | 未指定时如何补 |
|---|---|---|
| 主体 | 人数、角色名/原创身份、物种、不可改特征 | 根据题意选择，避免无关路人 |
| 动作 | 当前一刻谁做什么、作用于谁/何物 | 选择一个可读动作，不列连续剧情清单 |
| 外貌 | 发型发色、眼睛、标志物、必要体型差 | 只补有辨识度的细节，不用统一美少女脸替换所有人 |
| 服装 | 用户指定衣装、主色、结构与道具关系 | 与场景和动作匹配；同人换装应有意识区别原设 |
| 镜头 | 景别、机位、观看方向、主体占比 | 根据看脸/看动作/看世界选择一个主目标 |
| 环境 | 地点、近中远景、接触面、道具 | 原创时补具体场所；极简需求保持简洁 |
| 美术 | 媒介、主色、主光、阴影、材质 | 选择相容方案，不把所有炫光效果一起叠加 |
| 可见文字 | 真正要印出的文字、载体、位置、换行 | 没有明确印字需求不自创标题、署名或广告文案 |
| 格式/语言 | Caption/Tag/Layout，英文/中文/双语 | Caption + 英文 |
| 尺寸 | 用户指定尺寸或宽高比 | Layout 必须落实尺寸；无指定通常 1024×1024 |

用户已给的硬约束优先于默认值。只有缺失项会**实质改变任务**时才澄清（例如「单张还是四格」、
「用户指定尺寸不符合 16 倍数」）。普通发型、背景小道具与相容光照可自行合理补全。
用户指定 1000×1500 等非 16 倍数尺寸时，**指出冲突并给出邻近可用尺寸**，不能静默改掉再宣称
完全照办；生成画布尺寸不确定时，不把它当已知事实。

### §3.1 高完成度画面的执行顺序（内部顺序，不写进输出）

1. **先定焦点与镜头。** 明确观众首先看脸、动作、人物互动还是环境；选相容的景别、相机所在位置、
   观看方向和主体大小。用近处物体更大、身体缩短关系、遮挡、台阶或梁柱递减说明空间。只写
   「电影感、广角、动感」不算落实；全身动作要给必需肢体和道具留边。
2. **再定动作与接触。** 固定一个时刻，逐一确认身体朝向、支撑或悬空状态、近手/远手做什么、
   接触哪个部件。**共享道具只计一件**；盾牌绑在哪条前臂、绳索连在哪里、鞋底踩在哪里，
   要用可见关系写明。镜面要区分真人、镜中实例和相机位置。
3. **再落实光影与材质。** 写光源位置和方向、照亮的具体表面、保留的阴影，以及必要的反射/填充。
   需要看表情时给面部可读的明暗层次；纯剪影等明确需求除外。同一束光下，织物呈宽缓明暗、
   金属呈较锐反光、玻璃呈透射与边缘反光。
4. **最后分配细节。** 将「精致、细节拉满」转成与题材有关的可见细节：焦点处的眼神、发束交叠、
   衣装结构、握持接触或关键道具；次要区域保留结构，远景适当简化。
5. **成稿前删冲突与重复。** 检查取景能否容纳动作、道具是否重复、左右和支撑是否一致、
   光影有无互相抵消。删除空泛质量形容词、重复风格句和无关细节。

以上用于提高描述一致性，不能保证每次成图都高质量。优先级为**用户硬约束与身份/动作可读性**，
再组织镜头、光影与细节；不能为了「美学」擅改角色、衣装、剧情或增加文字。

## §4 场景组装决策表

| 类型 | 必写内容 | 推荐镜头/空间 | 主要失败点与修正 |
|---|---|---|---|
| 单人角色展示 | 身份、辨识锚点、衣装、一个姿态、视线 | 中景/全身，背景按用户需要 | 不把中景写成脸特写，也不默认为空背景 |
| 面部主视觉 | 脸型/眼神、可见饰物、主光作用、微表情 | 半身或胸像，有环境线索 | 减少远景抢戏；不是只加「漂亮脸」 |
| 日常生活 | 在真实场所做一个活动、接触道具 | 平视中景、桌/窗/门构建深度 | 让人物真的读书、喝茶，而非摆姿势后堆背景 |
| 环境叙事 | 事件、人物落点、前中后景、主光与气氛 | 中远景/广景，人物占比相应减小 | 避免人物突然占满画幅 |
| 剧情主视觉 | 身份、当下动作、事件/冲突、观众关系、媒介 | 斜线或前景引导，必要时近手透视 | 不强制每图灾难；宁静等待也能有故事 |
| 动态/战斗 | 一个动作瞬间、重心、支撑/腾空、武器握持 | 全身或中远景、机位服务动作 | 不用 bbox 代替关节；不一次要求三个瞬间 |
| 双人互动 | 精确人数、分别外貌衣装、站位、谁对谁做什么 | 能容纳双方的中景/全身 | 两套属性分句绑定；同一件交接物只写一件 |
| 群像 | 人数、主次分组、可辨锚点、各自动作 | 足够宽的场景；严格占位可 Layout | 降低每人细节密度 |
| IP 同人 | 角色+作品、必要外观锚点、指定形态/衣装 | 随创作目标 | 角色辨识与美感分开检查 |
| 文字海报 | 实际文案、阅读顺序、字区与图像主次 | 多字块优先 Layout | 先安排可读面积；不用装饰字体掩盖错字 |
| 漫画/多格 | 格数、读序、每格一刻、连续特征、对白 | Layout 全局坐标规划 | 重复出场不等于多名不同角色 |

**剧情主视觉五要素**：① **身份**——在这件事中是谁（不只是职业名）；② **当下动作**——此刻可见的
动作与一件关键道具；③ **事件/环境压力**——即将关门的列车、窗外骤雨（不必都是世界毁灭）；
④ **观众关系**——交给你、与你对峙、被你撞见，或旁观其独处；⑤ **具体媒介与美术**——线条、上色、
色彩、相机和光照怎样支持这一刻。

## §5 人数、身份与外貌绑定

**原创与 IP**：原创人物用可见外观与身份描述，**不杜撰作品名**。IP 创作写角色名与作品名，
并补能区分该角色的关键锚点：发色/发型、眼睛、耳/角/翼、标志衣装或饰物。数量按需要，
不机械凑「必须五个」。有不同形态、时装、时期时先确定一个版本；缺乏可靠依据的复杂服饰细节
不当成官方设定。名字可能混淆时带作品名或有效别名（例如 Overlord 的雅儿贝德，不只写
`Albedo`）。保留有辨识度的通用角色名或别名，不生硬翻译专名。

**多人不是一串共用属性**（硬规则：属性必须**按角色分组**连续写完再切换，**严禁交叉排列**）。

弱写法：`two women, red hair, black hair, blue jacket, yellow coat, holding a box`——颜色、
衣物和动作容易在两人之间漂移。

更明确的写法：

```text
Exactly two women stand on the platform. The short red-haired woman on the left wears a blue jacket and black trousers; she holds out one small green box. The tall black-haired woman on the right wears a yellow coat and white trousers; she reaches toward that same box. Both look at the box between them.
```

`A/B` 可在内部规划中使用，最终描述还要给出可见身份锚点。不要假设「character A」像编辑器对象
ID 一样有强制绑定能力。**Layout 里每个 `character` 项也需要完整描述**，JSON 不能替你解决语义遗漏。

精确人数时区分主角与背景人群：「只有两人、没有路人」与「两个主角，背景人群不突出」是两种不同
需求。镜面倒影、画中人、屏幕里的人应明确其性质。

**左右有两个坐标系**：**画面左/右**（从观众看图的方向，适用于站位和 bbox）与**角色自身左/右**
（人物自己的解剖侧，转身后与画面方向不同）。优先写视觉可检查的关系，例如「靠近镜头的手握住
杯柄，远侧手托杯底」。确实需要自身右手时写明 `her anatomical right hand`，再结合身体朝向检查；
不要同时给出相反的画面左右暗示。模型仍可能画错，不把措辞当硬保证。

## §6 服装、道具与材质

写清主衣装、主色、结构、实际穿着状态和一两处可辨细节。换装任务保留脸、发型、眼睛和角色标志，
衣服本身可按用户要求变；严格原设任务不擅自换衣。衣装要服务动作：奔跑时衣摆和重心相容，
雨衣能挡雨，骑行服适合机车，舞台衣装保留表演器材。用户要明确跨风格融合时可以混搭，
只检查是否有设计理由。

道具写**状态与接触**：书是打开还是合上；钥匙握在指间还是放在掌心；伞是撑开还是收拢；
剑是握柄下垂、入鞘还是正在挥动。小道具靠近脸或手时可能抢焦，数量不要无意变多。

材质用**响应光线的方式**区分，而非给所有东西统一 `shiny`：棉布漫反射、绸缎沿褶皱长高光、
皮革窄亮边、金属反射、玻璃透光与边缘反光、湿石板反射破碎光带。金属不必自发光；羽毛、
黑发和黑衣也不能全部融合成一个黑块。

## §7 姿势、动作与受力

按「**身体朝向 → 重心/接触面 → 一个主要动作 → 手/道具关系 → 次要运动**」组织。
不要把一段视频的开始、过程、结果压成同一张静图。

| 动作 | 建议明确 | 不应依赖的空泛词 |
|---|---|---|
| 站立回望 | 躯干仍朝前，头越肩转向后方，双脚落点 | `dynamic pose` 单独解决不了朝向 |
| 奔跑 | 一脚支撑/离地，另一腿摆动，身体前倾，风向 | 同时写完全静止、双脚平踩地面 |
| 坐在高墙 | 臀部承重位置，腿悬垂/屈起，手扶墙或持物 | 「漂浮」与「坐实在墙上」同时当主姿态 |
| 近手递物 | 哪只手、握持位置、道具靠镜头、脸位于中景 | 只写巨大手掌而不写握物关系 |
| 横向一字马 | 两腿向画面左右伸直，骨盆居中，躯干直立 | 与前后劈叉混为一谈 |
| 前后劈叉 | 一腿向前、一腿向后，侧面机位 | 正面图却要求完整看清前后腿长度 |
| 拉弓/挥剑 | 握持、手臂方向、肩胯扭转、武器轨迹 | 只堆 `action, fighting, intense` |
| 水下漂浮 | 无地面支撑，气泡上升，头发/衣料受水流 | 同时要求干燥贴身与强烈上漂 |

为了看清全身动作，明确留出头、手和脚的空间，并使用足够宽的画幅。想同时检查表情与足尖细节时，
应分成两个镜头/两张图，或明确多格。运动场景使用适合运动的正常服装，不为运动姿态添加无关
性化描述。复杂姿势失败时先减掉额外道具、多人交叠和极端透视，保住主动作，再逐项加回。

## §8 镜头、构图、透视与空间层次

| 主目标 | 景别与主体占比的语言 | 要舍弃什么 |
|---|---|---|
| 看眼神与饰物 | 胸像/半身，脸为焦点，留出耳/角/发饰 | 不同时要求看全身鞋履和巨大世界全景 |
| 看完整衣装/姿势 | 全身，头脚有边距，道具不裁切 | 眼睛细部不可能与大特写同样显著 |
| 看人物与事件 | 中景/中远景，动作和接触物可读 | 减少无关特效 |
| 看宏大环境 | 人物较小，场景占多数，前中远景分层 | 不再要求脸占全画面中心 |

焦距字样是**视觉意图**，不是实际摄影机标定。可以写 wide-angle / normal / telephoto，
再补物体的相对大小、遮挡和引导线；仅写 `24mm` 不保证正确透视。

**空间写法**：① 前景——选一个有作用的框景/遮挡物（近栏杆、树叶、门框），不能把脸遮没；
② 中景——主角与正在交互的物体，要有落脚或承重关系；③ 远景——递减结构、山体/街道/柱廊，
通过空气、水或光色简化；④ 引导线——铁轨、台阶、地板、屋顶梁、门框，指向一致的空间方向；
⑤ 留白——给视线、运动方向、翼/发丝或文字留出位置，留白不自动变成写标题的区域。

**身体、脸和视线分开描述**：身体背对相机但越肩回望，可以看见侧脸；「完全看不到脸」和
「清晰正面双眼」在同一人物同一瞬间不相容。俯视机位不要求角色一定低头，低机位也不要求仰头。
单人未指定视线时按事件选择：听歌可看向观众，读书应看书，花丘观星应望向天空；不要机械给每张
单人图强塞直视镜头。多人以互动与注意对象为准。

**镜面与多视图**：清楚标出镜面在哪、真人朝向和镜中能看到的部分；不要对镜像简单复制与真人
同向的肢体描述。镜面关系复杂时，优先使用清楚的真人朝向、简单姿态与单镜面。多格角色重复出现
要在每格重述身份，不把 `multi_panel` 当作跨格一致性功能。

## §9 美术设计：光影、色彩、细节与情绪

**光照必须有因果**，采用「**光源位置 → 被照亮的面 → 阴影/投影方向 → 反射/填充 → 环境空气感**」
组织。一个主光已经足够；需要时补一个相容的反射光或次光源，不把主光数量规定成模型硬限制。

弱写法：`cinematic lighting, dramatic lighting, beautiful lighting, detailed face`。

可执行描述：`Warm window light enters from frame left, illuminating the near cheek and orange
strands at her temple. The far cheek and neck keep a soft cool shadow, with a small reflected
highlight from the pale tabletop.`

**三个层级**：① **角色自身**——眉骨、鼻翼、下唇、下颌、颈部、眼窝与发丝怎样受光（只强调背景
光束，脸仍可能平）；② **角色与环境分离**——轮廓光、服装明度、暗部色差、前后景对比，不必每次
都用霓虹描边；③ **整个场景**——主色、暗部色、少量点缀色；距离增加时对比/细节递减。
脸部不等于写实肤质：二次元可用少量层次明确的色块、柔和过渡和有方向的高光。

| 气氛 | 可见因果 | 注意 |
|---|---|---|
| 日常窗边 | 大窗软光照近脸，远脸冷柔影，桌面有光斑 | 窗光不应从两侧同时当唯一主光 |
| 雨夜巷道 | 青灯与暖门分区，湿石板反射两者，深处压暗 | 雨滴在灯旁显著，别让每处都泛白 |
| 黄昏远行 | 低太阳暖边、长影、冷檐影，远山雾气 | 镜头方向和影子方向一致 |
| 月夜烛光 | 冷月勾边，近烛暖脸，暗部仍有色 | 把蜡烛写成实际可见/可推断光源 |
| 水下遗迹 | 顶部透光、近石焦散、远处深蓝衰减 | 不用空气中的尘埃代替水中悬浮物 |
| 舞台演出 | 软主光照脸，彩色边光分发丝，背景暗 | 不把所有肤色染成同一片强紫光 |
| 雪夜书店 | 窗内暖光照脸，积雪冷反射填暗部，远街蓝 | 雪点近大远小，不盖住眼睛 |
| 夕阳剪影 | 大面积暗主体、边缘暖亮，表情可不突出 | 真正剪影与清晰精细正脸不是同一优先级 |

**细节的主次**：按 §3.1 先完成大形、空间与明暗，再选与画面有关的材质重点；两到四类只是创作
参考，不是数量配额。明确「哪里细、细在哪里」：焦点处可写发束的前后交叠、袖口折线、握柄处
手指的包覆、金属接缝的窄反光；远处只保留可辨轮廓和递减结构。**不要把所有示例机械加进每张图。**
二次元细节也可以是准确的线条和色块，不等于摄影毛孔、噪点或密集装饰。

光粒子、花瓣、雨滴、雾、火星都要有空间尺度和来源。一个方向的风同时影响头发、围巾、衣摆和
落叶；不能只把长发当装饰曲线，却让其他元素朝相反方向飞。

画面情绪通过**可见行为**表达：迟疑的手、未寄出的信、空站台、两人之间的距离。`melancholic`
等词可以概括，但不能代替事件。

## §10 Tag 模式与自然语言模式的衔接

支持自然语言、Tag 和 Layout。其他模型的推荐 Tag 顺序是 Quality → Score → Meta → Year →
Character → Series → Artist → General；**本模板移除 Quality、Score、Artist，年份不默认补**，
因此可用的精简顺序是：

**具体媒介 Meta（可选）→ Character → Series → General**

人数、外貌、衣装和动作归入实际内容，不要套用其他模型的槽位规则。用户未要求 Tag 时，优先写
有明确主语、关系和因果的自然语言。Tag 可做紧凑身份/外貌锚点，自然语言补交互与空间；避免把
同一内容重复两遍。不要引入其他模型的括号权重、`BREAK`、分角色扩展指令或区域扩展语法；
普通括号可用于角色别名。

Tag 例子（不含质量词/画师）：

```text
Japanese 2D anime illustration. Hatsune Miku, Vocaloid, solo, turquoise twin-tails, turquoise eyes, rectangular hair ornaments, headset microphone, gray top, turquoise necktie, black detached sleeves, listening to music, glass conservatory, warm window light
```

中文描述版应自然改写，不必逐字把标签翻成硬凑词串。精确的多人交接、镜面或透视关系，
优先用完整句子表达。

## §11 可组合的双语表达库（用法约束）

§11 的素材库是**描述素材，不是必须逐条加入的咒语**，也不是单词效果的官方保证。按画面选择
相容项，优先组成有主语的句子。不要因为词库有这个词，就给所有角色都加角、翅膀、霓虹、雨滴
和大风。分七类：外貌与辨识 / 衣装与风格配方 / 姿态、手势与接触关系 / 表情与可见情绪 /
镜头与空间语言 / 环境与事件配方 / 光线、材质与配色句库。需要成句素材时读
`references/anime-prompt-template-zh.md` 的 §11。

## §12 Layout：格式、字段与坐标

Layout 是**结构化提示词**。框表达目标占位，不是硬裁切、姿态骨架、三维相机或逐像素约束。
先设计图文主次与人物关系，再填写框；JSON 不能代替动作、透视和光影描述。

### 画布与内部草稿

先确定 `width` × `height`，**宽高必须是 16 的正整数倍**，与最终图像尺寸一致。用户只给宽高比时
选择相容尺寸（例如 16:9 可用 2048×1152）；没有比例依据时可用 1024×1024。明确指定的尺寸不合法时
指出冲突，不静默修改。**尺寸说明放在提示词之外。**

内部规划使用**左上角为原点**的像素框 `[x0,y0,x1,y1]`：`0≤x0<x1≤W`，`0≤y0<y1≤H`。
所有文字、漫画格内人物和道具都用**全图坐标**，不用百分比、归一化坐标或格内局部坐标。

需要保留可编辑草稿时，根字段为 `width`、`height`、`bbox_coord_space="abs"`、
`bbox_format="xyxy"`、`summary`、`items`。**草稿不能直接当作最终 Layout 交付。**

### 内容字段

| 字段 | 写法 |
|---|---|
| `summary.caption` | 必填非空字符串：**独立画风首句**，随后写全局场景、人数、观看/阅读顺序、主次和共享光照 |
| `summary.meta` | 可选字符串数组，只放有用的媒介、题材；不放质量词和自动添加的画师 |
| `summary.palette` | 可选字符串数组，写全局配色 |
| `summary.canvas` | 可选，取值 `single`、`multi_panel` 或 `collage` |
| `items` | 非空**扁平**数组，所有对象都在同一层 |
| `item.label` | 必填，只能为 `character`、`object` 或 `text` |
| `item.caption` | 必填非空字符串，写该项的外观、动作、关系、材质；文字项写字体倾向、层级、颜色和载体 |
| `item.bbox` | 必填四个坐标，遵循所处草稿/成稿格式 |
| `item.text` | `text` 项必填非空字符串，保存真正印出的文字 |
| `item.tags` / `item.palette` | 可选字符串数组，只补该项特征或配色，不替代 `caption` |

**不增加** `style`、`id`、`children`、`parent`、`panels`、`panel_id`、`elements`、
`negative_prompt` 等字段。标签中没有 `panel`；实际可见的漫画格背景可用 `object` 描述。

### 最终输出格式（坐标换算硬规则）

最终根字段**仅为** `summary`、`items`、`bbox_coord_space="abs_centralized"`、
`bbox_format="yxyx"`。**不含 `width` 和 `height`**，使用整数中心坐标，以**一物理行紧凑 JSON**
交付。画风是 `summary.caption` 的第一句，不在每个 item 内重复。

整数像素草稿 `[x0,y0,x1,y1]` 转换为：

```text
[y0-H/2, x0-W/2, y1-H/2, x1-W/2]
```

例如 1024×1024 画布，`[100,320,440,760]` 转换为 `[-192,-412,248,-72]`。**原点和数组顺序同时
变化；负数正常。**1536×1024 画布必须分别减宽中心 768 和高中心 512，不能两轴都减同一个数。

有小数边时，先对左/上边**向下取整**、右/下边**向上取整**，再减画布中心并改为 yxyx。优先使用
官方编译器或计算工具完成机械转换；逐项检查结果，不凭目测估算。转换失败时修正草稿，不能仅
更换格式标记掩盖错误，也不能声称未经执行的编译已通过。

改尺寸后若要保持相对占比，先按新旧宽高分别缩放草稿坐标，复查构图后重新转换；只改尺寸不会
自动缩放对象。

## §13 Layout 的人物、文字、多人和多格规则

**拆项与合并**：每个需要独立位置的完整人物用一个 `character` 项；人物衣服、手持道具及头发若
无需独立定位，可在其 caption 里描述。桌上独立杯子、中央行李箱、墙上招牌等单元用 `object`；
如果道具已有独立 item，人物 caption 要说明与同一件道具的关系，避免复制。要求完整羽翼、长发或
全身衣摆时，给该人物框预留相应范围，不要用脸大小的框承载全身。**不给同一人物的「脸」和
「身体」各建一个 character**。背景风格和全局光照优先放 summary。自然遮挡可以框重叠；框的先后
顺序不当作硬性图层 z-order，用描述说明谁在前、谁被遮挡。

**双人/多人**：summary 写精确人数、整体关系和相容光照；每个 character caption 自带发色发型、
衣服主色、动作、视线，主语如「左侧短红发女性」要与它的 bbox 一致。交接动作涉及同一个道具：
若道具单列 object，应把其框放在交互区，并写两人分别「递出」和「接向」该同一件物体，不能写
每人都各握一个独立盒子。精细手部仍可能失败，bbox 不是骨架。只要要求大致左右、自然对话，
Caption 就可用；需要严格占位比例、留出中间文字区、两人不能互相挡脸等再选 Layout。

**文字项**：真正印字用 `label="text"`、`text` 保存原文，`caption` 描述字的颜色、大小层级、
字体倾向、载体。**不能只写「这里是标题」让模型自己编文案。**独立排版的标题、正文、脚注分成
不同 item；同一段固定换行可在一个 `text` 字符串里用 `\n`。JSON 文件中的 `\\n` 在解析后表示
真正换行；不要双重转义成字面反斜杠 n。中文提示词也必须使用 ASCII 双引号作为 JSON 语法引号，
不能换成中文弯引号。同一对象上的文字也使用**全图坐标**：若招牌框是 `[100,100,500,300]`，
牌中文字也给画布上的实际位置，不从招牌左上角重新计为 `[0,0,...]`。先检查字号能否容纳文字；
字数多时增加画布/字区、减少装饰或拆图，不擅自删掉用户要求的字。小字仍可能错字，位置正确
不等于内容逐字正确。

**多格漫画与拼贴**：`canvas="multi_panel"` 只标明整体类型。需要实际格框时，在 summary 描述
读序和边界；用 `object` 表示每格可见背景区域，再用 character/text 项在对应**全局区域**布置
人物与对白。全文件 `items` 仍是扁平数组，不使用 `panels`、`children`、`parent`、`panel_id`
或局部坐标。某一角色在两格各出现一次时，重述同一身份特征并说明重复出场。不要为了画分镜引入
其他模型的分角色或区域扩展语法。多个框不提供面部一致性、镜头物理一致性或精确对白气泡形状的
保证。

**JSON 常见错误**：

| 错误 | 为什么有问题 | 正确做法 |
|---|---|---|
| 自创 `prompt`/`negative_prompt`/`seed` 根字段 | 不属于 Layout 草稿规范 | 仅用 summary/items 保存画面内容 |
| 给 items 加 `children` | 官方扁平 schema 不接受 | 所有单元列在同一 items，坐标都按全图 |
| `label="panel"` | 非官方枚举 | 可见格背景用 object，组织类型放 `summary.canvas` |
| 草稿写 0.1–0.9 | 被当成不到一像素的实际数值 | 使用真实像素，不用归一化 |
| 直接把 xyxy 草稿标成 yxyx | 坐标顺序和原点不一致 | 由编译器转换 |
| 改尺寸不改框 | 不会保持相对占比 | 重新规划或缩放草稿，再编译 |
| 框超过画布 | 编译器会报错，不自动裁切 | 修正边界，不绕过检查 |
| `x0=x1` 或 `y0=y1` | 框无面积 | 给出正宽高 |
| 两个同名 JSON 键 | 标准解析可能悄悄覆盖 | 检查并删除重复键 |
| JSON 有注释/尾逗号 | 非标准 JSON | 注释放说明文件，删尾逗号 |
| 把 `bbox` 字样写成屏幕上的字 | 规划混进画面 | 坐标留在字段，caption 只描述可见内容 |
| caption 说左，框却在右 | 文本与几何冲突 | 保持两者一致 |
| 只写人物框，不写外观 | 角色身份缺失 | 每人 caption 独立绑定锚点 |
| 只放 `text` 不给文字 caption | 缺少必要字段与排版意图 | 加 typography/surface 描述 |

## §14 修改提示词

**每次修改均输出完整可用提示词，不只给替换片段。**保留用户已经认可的身份、衣装、画风、剧情、
镜头、配色和光源，只调整受影响的部分。仅改画风时只替换独立首句，并完整返回后文；Layout 只修改
必要的描述和框，重新检查坐标。

| 问题 | 优先调整 |
|---|---|
| 人物太大、环境不足 | 改主目标、景别、机位和主体大小，给远景留下空间 |
| 脸平、背景抢眼 | 让主光作用到脸部，保留有形状的面部/颈部阴影，降低背景竞争 |
| 角色混淆 | 核对作品、名字/别名、形态、衣装与辨识锚点 |
| 多人串色串衣 | 独立主语绑定属性，必要时使用独立人物框 |
| 手与武器脱离 | 明确哪只手握哪个部件、身体受力与遮挡 |
| 共享物体变成多件 | 所有相关描述指向同一件物体，整理重复的 object 项 |
| 全身动作裁脚 | 调整景别和主体大小，为头、手、脚与道具留边 |
| 镜像混乱 | 明确镜面、真人朝向、可见镜像和相机位置 |
| 字区拥挤 | 增加字区和留白，分清标题、正文、小字，不擅自删用户文案 |
| 画面繁杂 | 减少次要装饰、特效和重复细节，保留焦点附近的结构与材质 |

**不要用增加质量形容词替代问题定位。**提示词改写只能明确意图，不能保证其他画面部分完全不变，
也不能把 Layout 当作局部编辑工具。

## §15 输出前检查（内部执行，不写进输出）

1. **语言与交付**：英文默认；指定中文或双语时正确切换；每份都是完整正向内容。
2. **画风**：仅有一条**独立首句**，遵守「用户画风/参考图 → 表现方式 → 题材默认」优先级。
3. **身份与实例**：名字、作品、形态、衣装和关键锚点一致；人数、镜像、屏幕人物、跨格重复实例不混淆。
4. **归属与接触**：每人属性有独立主语（**按角色分组**，不交叉）；手部、道具、支撑/悬空、
   身体方向及视线相容。
5. **镜头与空间**：景别、机位、主体大小、透视、遮挡和必要留边相容；一个主视觉目标清楚。
6. **光影与细节**：光源和作用面有因果，材质反应有区别，焦点与远景细节有层次。
7. **文字**：只生成用户真正要求印出的内容，原文、大小写、标点和换行保留，字区能容纳文字。
8. **纯净输出**：无自动添加的质量 tag、评分、画师、标题、署名、流程注释或生成参数。
9. **Layout**：字段枚举正确，items 扁平，框面积为正且不越界，描述与框一致，text 项完整；
   最终是一行 `abs_centralized` / `yxyx` 整数框 JSON，**不含尺寸字段**。

冲突判断**限定同一对象、同一部位、同一瞬间**：身体背向但越肩回望合理，一人坐一人站合理，
第一人称看见对面全身合理；不能机械全局互斥。单镜头的全脸大特写与完整全身展示、同一只手同时
张掌与握拳、同一物体同时打开与合上，则需要选一个状态或明确分格。

保持用户的极简、平涂或剪影方案，不为凑「完成度」强加写实材质、密集背景和夸张特效。结构合法
不代表模型能完全遵循，复杂人体、镜面与小字不作绝对保证。
